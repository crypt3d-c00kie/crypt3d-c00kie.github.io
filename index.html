03 — Architecture decisions · Kissflow lakehouse

Decisions of record.

the calls behind the diagram — and the cost of each

Sources → Bronze

Land it raw, decide later.

Decision

Ingest 10+ heterogeneous sources into a Bronze layer on S3 with schema-on-read; catalog in Glue.

Considered

Model straight into the warehouse — warehouse-only ingest.

Why

Raw and curated stay decoupled — historical data reprocesses independently, without re-ingesting from source systems.

Tradeoff

An extra hop and storage layer to operate; schema drift surfaces later, in Silver, instead of at ingest.

Bronze → Silver

Merge, don't reload.

Decision

Rebuilt the transform layer in PySpark + Polars around incremental merge/upsert with automated schema evolution.

Considered

Full-refresh batch rebuilds each run.

Why

Only changed partitions are recomputed — batch pipeline runtime dropped 40%.

Tradeoff

Merge logic and idempotency have to be exactly right; late and duplicate data handling moves into the job.

from delta.tables import DeltaTable

# spark.databricks.delta.schema.autoMerge.enabled = true
(DeltaTable.forName(spark, "silver.orders").alias("t")
    .merge(source.alias("s"), "t.order_id = s.order_id")
    .whenMatchedUpdateAll()
    .whenNotMatchedInsertAll()
    .execute())
Across the pipeline

A bad row shouldn't reach a dashboard.

Decision

dbt tests (uniqueness, referential integrity, not-null) plus Great Expectations contracts and PII/RBAC checks, all wired into CI.

Considered

Post-hoc data-quality monitoring and alerting only.

Why

Schema and data-quality regressions are caught before they reach production marts; deploy cycles went from days to hours.

Tradeoff

CI runtime and test maintenance grow with the model graph.

# models/marts/_schema.yml

Silver → Gold

Model for the question, not the source.

Decision

Snowflake dimensional (star-schema) models and materialized views; SQL tuned with CTEs, window functions and clustering keys.

Considered

Serving Silver tables directly to BI.

Why

Sub-second dashboard loads and predictable query cost — warehouse compute spend down 30%.

Tradeoff

Modelling effort up front; materialized-view refresh and clustering need upkeep.

create or replace table gold.account_health
  cluster by (dt) as
with daily as (
    select account_id, dt, sum(events) as events
    from silver.activity
    group by 1, 2
)
select *,
    avg(events) over (
        partition by account_id order by dt
        rows between 6 preceding and current row
    ) as events_7d
from daily;
Serve / cost

Own the reporting layer.

Decision

Built a native ETL/reporting framework to replace a third-party BI tool.

Considered

Renew the third-party BI licence.

Why

Eliminated roughly $40,000/yr in licensing; reporting logic now lives in version control next to the pipelines.

Tradeoff

A framework to maintain in-house — feature parity is on us.

Cloud Cost Optimization Dashboard

PYTHON · SNOWFLAKE · STREAMLIT · AWS LAMBDA

Flags idle warehouses and inefficient queries, then puts real-time compute cost in front of the teams that generate the spend.

select warehouse_name,
       date_trunc('day', start_time) as day,
       sum(credits_used)             as credits
from snowflake.account_usage.warehouse_metering_history
where start_time >= dateadd(day, -30, current_date)
group by 1, 2
order by credits desc;
≈ 25% idle compute spend reclaimed
